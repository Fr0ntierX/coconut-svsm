Expand description

Retire a guest vCPU at the guest VMPL, then revoke a partition’s pages.

This is the reclaim step of the CMVM watchdog (uPolaris threat model section 9.3). Steps, in order:

  1. Check the target is a guest-created, in-use VMSA that is not the calling vCPU’s, and that every page in pages is a 4K guest page that is not a registered VMSA or calling area.
  2. GHCB AP_DESTROY for the target’s APIC ID at the guest VMPL, before taking PVALIDATE_LOCK, so the host’s kick has time to land. Without it the retire still works but KVM is not told, and the VM stops at the target’s next VMRUN (measured on the lab part, 16 Nov 2026).
  3. Under PVALIDATE_LOCK, RMPADJUST the VMSA page to no access at the guest VMPL, which clears the VMSA attribute. Success is the hardware proof that the vCPU is out of guest mode and can never re-enter. The APM allows FAIL_INUSE here, which is retried until opts.inuse_deadline. On the parts we have measured the hardware never returns it: while the target is in guest mode the instruction raises a nested page fault on the VMSA page, the host resumes it, and it runs again. VMPL0 never regains control during that loop, so its length is set by the host (about 7 us when the AP_DESTROY kick lands, about 0.8 ms when it misses and the target waits for its next timer exit). A hostile host can stretch it, which is denial of service.
  4. Unregister the VMSA, revoke every guest VMPL’s access to each page in pages, then zero the old VMSA page and give it back to the guest VMPL as core_delete_vcpu does. Scrubbing anything the vCPU held is only safe after step 3, never after the AP_DESTROY return.

The guest kernel must have taken the target CPU offline. An NMI sent to a retired vCPU makes KVM refuse to run it and stops the VM, and the other CPUs wedge waiting on it otherwise.

Partition pages are revoked at 4K. A page the guest validated as part of a 2M RMP entry returns FAIL_SIZEMISMATCH and is reported as RetireError::PageRevoke.

The stats come back with the error too, filled in as far as the call got. The watchdog (protocols::watchdog) calls it when a watched vCPU misses its deadline.

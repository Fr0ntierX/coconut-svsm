SVSM_REQ_PARTTEST_DERIVED_KEY_HASH 🔒
Ask the PSP for a VMPL0 derived key and return the first 24 bytes of its SHA-384 in rcx, rdx and r8. Input: rcx = GUEST_FIELD_SELECT, rdx = ROOT_KEY_SELECT. This exists to check on silicon that the key the DICE root will use (F0X-80) is stable for one image and changes with the selected fields. The key itself is the monitor’s root secret and never leaves VMPL0; only a one-way hash does, and only in parttest builds.
SVSM_REQ_PARTTEST_DICE_ATTEST 🔒
Measure a guest memory region as a partition and return its EAT (F0X-80): the monitor token, signed by the hardware-rooted monitor alias, carrying the partition’s nested token and the monitor’s endorsement of the partition’s measurement and alias key. With call 5’s root it is a complete version 2 evidence bundle.
SVSM_REQ_PARTTEST_DICE_ROOT 🔒
Write the monitor’s hardware root endorsement (F0X-80) to the 4K guest page at rcx: the alias public key (97-byte SEC1 point) followed by the VMPL0 attestation report that binds it in REPORT_DATA. A verifier checks the report against the VCEK chain and recomputes REPORT_DATA from the key. Only public values leave VMPL0; the CDI and the alias private key do not.
SVSM_REQ_PARTTEST_FAULT_INJECT 🔒
Arm one injected failure at a named step of the retire, START_VCPU or watchdog paths (faultinj), so their error paths can be driven on hardware. In: rcx bits 0-11 = FaultStep code, or 0 to clear, bits 12-63 = a page-aligned VMSA GPA the fault is keyed on (0 for any target; only the retire steps name a target). rdx = the status the failing step returns, where it returns one (for FAIL_INUSE, how many fake results the retire sees, u64::MAX for all of them). r8 bits 0-31 = hits at the step to let through first, bits 32-63 = how many hits fail (0 means 1). Out: rcx = the step of the fault this replaces (0 if none), rdx = how many times it fired, r8 = failures it had left.
SVSM_REQ_PARTTEST_GRANT_WRITE 🔒
Restore read/write/execute for the guest VMPL on one 4K page.
SVSM_REQ_PARTTEST_NOOP 🔒
Do nothing and return success. Times the guest -> VMGEXIT -> hypervisor -> VMPL0 -> back round trip with no work inside it, which is the relay cost any hypervisor-mediated partition switch has to pay (F0X-93 vmsa_reentry). VEIL reports 7,135 cycles for a relayed domain switch and NestedSGX 32-34k, so this is the term to compare against those.
SVSM_REQ_PARTTEST_RETIRE_VCPU 🔒
Retire a guest vCPU and revoke a partition’s pages (F0X-75 watchdog reclaim), through core::retire_guest_vcpu. The guest must take the target CPU offline first.
SVSM_REQ_PARTTEST_REVOKE_ALL 🔒
Drop every permission for the guest VMPL on one 4K page, read included. REVOKE_WRITE keeps read because B runs read-only: page tables must stay readable for the hardware walker at the partition’s VMPL. This exists only to tell whether the wedged-vCPU behaviour is specific to read-only or is general to any RMP permission violation (F0X-301, experiment 2).
SVSM_REQ_PARTTEST_REVOKE_WRITE 🔒
Drop write for the guest VMPL on one 4K page, leaving read in place.
SVSM_REQ_PARTTEST_START_VCPU 🔒
Start a guest-built VMSA on another vCPU (F0X-75 watchdog tests). In: rcx = VMSA GPA, rdx = calling area GPA, r8 = APIC ID, as CREATE_VCPU. Runs CREATE_VCPU’s checks and registration, then sends GHCB AP_CREATE at the guest VMPL from VMPL0, so the guest kernel needs no GHCB access of its own to hand a vCPU it took offline to a partition payload. If AP_CREATE fails (START_ERR_AP_CREATE) the VMSA stays registered but never ran, and call 7 retires it.
SVSM_REQ_PARTTEST_WATCHDOG_ARM 🔒
Arm a watchdog slot (watchdog::watchdog_arm). rcx = 4K request page: VMSA GPA, heartbeat GPA (8-byte aligned), deadline in TSC ticks, page count (at most WATCHDOG_MAX_PAGES), then that many 4K GPAs to revoke on reclaim, all u64. rdx = retry policy (watchdog::RetryPolicy): 0 for the default, or ARM_POLICY_SET with bits 0-15 = plain retries and ARM_POLICY_NO_FORCE to never force. r8 = with ARM_POLICY_SET, the retry window in TSC ticks (0 for none). Out: rcx = slot index.
SVSM_REQ_PARTTEST_WATCHDOG_DISARM 🔒
Free a slot that is armed, reclaimed or failed. In: rcx = slot.
SVSM_REQ_PARTTEST_WATCHDOG_STATUS 🔒
Write one slot’s record to a 4K guest page. In: rcx = slot, rdx = page. The record is WATCHDOG_STATUS_WORDS u64s, laid out in watchdog_status.
SVSM_REQ_PARTTEST_WATCHDOG_TICK 🔒
One watchdog period (watchdog::watchdog_tick). Only the first vCPU that ticks may tick again. Out: rcx = armed slots checked, rdx = slots whose vCPU was retired in this tick (bitmask), r8 = VMPL0 ticks spent (bits 0-31) | slots that finished with an error (bitmask) << 32 | slots whose retire failed and is retried next tick (bitmask) << 48. A slot retired with a clean-up error (ReclaimedPartly) is in both of the first two.

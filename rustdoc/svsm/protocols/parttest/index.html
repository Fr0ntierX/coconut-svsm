SVSM_REQ_PARTTEST_DERIVED_KEY_HASH 🔒
Ask the PSP for a VMPL0 derived key and return the first 24 bytes of its SHA-384 in rcx, rdx and r8. Input: rcx = GUEST_FIELD_SELECT, rdx = ROOT_KEY_SELECT. This exists to check on silicon that the key the DICE root will use (F0X-80) is stable for one image and changes with the selected fields. The key itself is the monitor’s root secret and never leaves VMPL0; only a one-way hash does, and only in parttest builds.
SVSM_REQ_PARTTEST_DICE_ATTEST 🔒
Measure a guest memory region as a partition and return its EAT (F0X-80): the monitor token, signed by the hardware-rooted monitor alias, carrying the partition’s nested token and the monitor’s endorsement of the partition’s measurement and alias key. With call 5’s root it is a complete version 2 evidence bundle.
SVSM_REQ_PARTTEST_DICE_ROOT 🔒
Write the monitor’s hardware root endorsement (F0X-80) to the 4K guest page at rcx: the alias public key (97-byte SEC1 point) followed by the VMPL0 attestation report that binds it in REPORT_DATA. A verifier checks the report against the VCEK chain and recomputes REPORT_DATA from the key. Only public values leave VMPL0; the CDI and the alias private key do not.
SVSM_REQ_PARTTEST_GRANT_WRITE 🔒
Restore read/write/execute for the guest VMPL on one 4K page.
SVSM_REQ_PARTTEST_NOOP 🔒
Do nothing and return success. Times the guest -> VMGEXIT -> hypervisor -> VMPL0 -> back round trip with no work inside it, which is the relay cost any hypervisor-mediated partition switch has to pay (F0X-93 vmsa_reentry). VEIL reports 7,135 cycles for a relayed domain switch and NestedSGX 32-34k, so this is the term to compare against those.
SVSM_REQ_PARTTEST_REVOKE_ALL 🔒
Drop every permission for the guest VMPL on one 4K page, read included. REVOKE_WRITE keeps read because B runs read-only: page tables must stay readable for the hardware walker at the partition’s VMPL. This exists only to tell whether the wedged-vCPU behaviour is specific to read-only or is general to any RMP permission violation (F0X-301, experiment 2).
SVSM_REQ_PARTTEST_REVOKE_WRITE 🔒
Drop write for the guest VMPL on one 4K page, leaving read in place.

adjust_guest_page 🔒
Maps the guest page named by rcx and applies flags to it for the guest VMPL. The address must be 4K aligned and inside a valid guest physical region, which is the same check the core PVALIDATE handler applies, so a guest cannot point this at SVSM-private or hypervisor memory.
